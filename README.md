## Career strategy

### Primary route

**Backend Software Engineering + Cloud + Applied AI**

1.  Use existing Laravel/PHP experience to target jobs immediately.
2.  Refresh Python, SQL, APIs, testing, and modern engineering
    practices.
3.  Build one well-tested backend service and deploy it.
4.  Learn AWS architecture and production operations.
5.  Add an evaluated AI feature to the same project.
6.  Decide about a master's degree using real program costs,
    requirements, and employment outcomes.

### Job targets, in order

1.  PHP/Laravel Developer, Backend Developer, Software Engineer, API
    Developer.
2.  Python Backend Developer and integration-focused engineering roles
    as skills become demonstrable.
3.  Application Support Engineer, Technical Support Engineer,
    Implementation Specialist, or QA Automation roles where
    software/database troubleshooting is useful.
4.  Junior cloud/DevOps roles after gaining hands-on deployment, Linux,
    networking, CI/CD, and monitoring experience.
5.  AI Integration / AI Application Engineer roles once the AI project
    demonstrates evaluation, security, reliability, and cost controls.

Do not assume you must restart at entry-level purely because of the
career gap. Apply to roles that match your real experience, while being
honest about skills that need refreshing.

### Session 2 --- Python baseline (2 hours)

**Primary resource:** [The official Python
tutorial](https://docs.python.org/3/tutorial/)\
Focus on these tutorial areas: - An informal introduction to Python -
More control-flow tools - Data structures - Modules - Input and output -
Errors and exceptions - Classes (review only if needed)

Because you already have programming experience, do not spend hours on
material you already know. Test yourself by writing code without copying
examples.

**Practice task:** Write a command-line program that: 1. Accepts a list
of service requests (hard-coded data is fine at first). 2. Validates
each request has an ID, customer, and status. 3. Filters requests by
status. 4. Counts requests by status. 5. Handles invalid or missing
fields without crashing. 6. Includes at least 5 tests using Python's
built-in `unittest` or `pytest` if already familiar.

**Acceptance criteria** - \[ \] Functions have clear names and focused
responsibilities. - \[ \] Invalid input is handled deliberately. - \[ \]
At least five tests pass. - \[ \] You can explain every line and every
design decision. - \[ \] AI-generated suggestions, if any, are reviewed
and understood.

### Session 3 --- Git and GitHub workflow (1--1.5 hours)

**Primary resources:** - [Git book --- Getting
Started](https://git-scm.com/book/en/v2/Getting-Started-About-Version-Control) -
[GitHub Skills](https://skills.github.com/)

Review: - Repository, working tree, staging area, commit - `git status`,
`git diff`, `git log` - Creating a branch, committing changes, merging -
`.gitignore` and avoiding secrets in repositories - Writing a useful
README

**Practice** - \[ \] Create a repository named `python-backend-refresh`
(or a similarly clear name). - \[ \] Add the Python exercise and
tests. - \[ \] Write a README with setup and run instructions. - \[ \]
Make at least 3 meaningful commits. - \[ \] Check that no passwords,
tokens, personal information, or employer code are committed.

### Session 4 --- Job-market scan and first applications (2--3 hours)

Search LinkedIn Jobs, Indeed, company career pages, and relevant
recruiters for: - Laravel Developer / PHP Developer - Backend Developer
/ Backend Software Engineer - Software Engineer - API Developer -
Application Support Engineer / Technical Support Engineer (as a parallel
route)

**Exercise** - \[ \] Collect 20 relevant job descriptions. - \[ \]
Record recurring requirements (for example: PHP, SQL, REST APIs,
testing, AWS, Docker, Python, communication). - \[ \] Mark each job as
strong / medium / weak fit. - \[ \] Submit 5 tailored applications if
suitable vacancies are available. If fewer are available, record the
search terms and broaden the geography or adjacent job titles. - \[ \]
Send 2 thoughtful messages to former colleagues, recruiters, or
engineering professionals. Ask for advice or a brief conversation, not
just "give me a job."

**Career-gap explanation (adapt honestly):**

> After three years of professional Laravel development in Jordan, I

> myself here. During this transition, I have been refreshing my
> engineering skills and building hands-on experience with Python, cloud

Only mention skills or projects you have actually started or completed.

### Session 5 --- Review and plan (30--60 minutes)

-   [ ] Record applications and any responses.

# Certification strategy

## Primary option: AWS Certified Solutions Architect -- Associate

**When:** Start foundational study around Month 3; prepare more deeply
in Months 4--5. Sit the exam only when practice results and
understanding indicate readiness.

**Why:** It reinforces cloud architecture knowledge useful to backend,
cloud, and platform roles.

**Official resources:** - AWS training:
https://aws.amazon.com/training/digital/ - Exam guide:
https://docs.aws.amazon.com/aws-certification/latest/solutions-architect-associate-03.html -
Certification overview: https://aws.amazon.com/certification/

**Budget rule:** Certification exams cost money. Verify current fees and
exam details before booking. Set a cloud budget alert before creating
paid resources.

## Optional alternatives --- do not pursue all at once

-   **AWS Certified Developer -- Associate:** consider if job listings
    and interviews point toward application development on AWS.
-   **AWS Certified CloudOps Engineer -- Associate:** consider if you
    move toward cloud operations.
-   **Google IT Support Professional Certificate:** consider only if you
    choose a help-desk/IT support route and need structured
    fundamentals.
-   **CompTIA Security+:** consider only if cybersecurity becomes a
    deliberate career direction.

A certificate does not replace work experience, interview preparation,
or portfolio evidence. Prioritize one relevant credential and practical
projects.

# Job-search operating system

## Weekly minimum

-   [ ] Review new vacancies and identify suitable roles.
-   [ ] Submit 5--10 tailored applications when enough suitable openings
    exist.
-   [ ] Contact a few relevant recruiters, former colleagues, or
    engineering professionals.
-   [ ] Practice at least one technical interview topic.
-   [ ] Record responses, rejections, and lessons.
-   [ ] Improve résumé targeting if there are no screening calls after a
    meaningful batch of applications.

## Troubleshooting the job search

-   **Few or no recruiter responses:** check role fit, résumé clarity,
    keywords, and whether you're applying to positions that require
    experience you don't yet demonstrate.
-   **Recruiter calls but no technical interviews:** practice explaining
    your experience, career gap, and project work concisely.
-   **Technical interviews but no offers:** record recurring gaps and
    practice them deliberately.
-   **Only support roles respond:** consider a technical bridge role if
    it offers relevant exposure, but keep applying to development
    positions.
-   **A suitable IT job offer arrives:** evaluate it seriously.
    Rebalance the study plan around the job rather than insisting on
    finishing every planned course first.

# Master's degree preparation

**Decision date:** Around the end of the 12-month plan, or earlier if a
good application opportunity appears.

## Candidate program types

-   MS Computer Science with distributed systems, cloud, software
    systems, or applied AI electives.
-   MS Cybersecurity only if security becomes a clear professional goal.
-   MS AI/ML or Data Science if you discover that you enjoy statistics,
    mathematics, and model development enough to pursue a more
    specialized path.

## Compare each program on

-   [ ] Accreditation and institutional legitimacy.
-   [ ] Total tuition and fees, not just advertised per-credit cost.
-   [ ] Curriculum depth and prerequisites.
-   [ ] Internship/co-op access and employer connections.
-   [ ] Graduate employment outcomes, with clear definitions and dates.
-   [ ] Schedule compatibility with employment.
-   [ ] Financial aid and realistic financing.
-   [ ] Admission deadlines and requirements.
-   [ ] Immigration/work authorization implications where applicable;
    verify your specific situation with the appropriate university
    office or qualified adviser.

Do not assume a master's degree is necessary to return to software
development. It should solve a specific career problem or create a
demonstrable opportunity.

# Operating principles

1.  **Employment first:** apply from Week 1; don't wait for
    certifications.
2.  **Use existing experience:** Laravel is an asset, not something to
    hide.
3.  **One main project:** extend it across backend, cloud, reliability,
    and AI instead of building many shallow demos.
4.  **Learn by building:** every major topic should produce a working
    artifact or documented skill.
5.  **Use AI as a tutor, not a substitute for understanding:** review
    generated code, write tests, and explain the result yourself.
6.  **Spend carefully:** free learning first; pay for exams and
    infrastructure only with a clear reason.
7.  **Adapt to evidence:** interviews, job descriptions, project
    feedback, and energy levels should change the plan.
8.  **Avoid burnout:** 8--12 hours per week is a sustainable target, not
    a reason to sacrifice sleep or health.
9.  **Be truthful:** don't claim professional experience or credentials
    you do not have.
10. **Review monthly:** the roadmap is a tool to guide decisions, not a
    rigid contract.

**Immediate next action:** complete Week 1 only. Do not try to study the
entire 12-month curriculum at once. At the start of Week 2, select the
specific materials based on what you learned and where you struggled in
Week 1.
